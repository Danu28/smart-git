## v1.0 Job to be Done

> **"I pasted a stacktrace — which commit broke this, and show me the diff without stashing my work."**
> Success = 10s answer on any repo, no repro script, no config.

## v1.0 Feature List

### P0 — Must ship (the wedge)

**1. `smart-git trace --stacktrace <file|stdin>` — Paste-to-Culprit core**
- Parse stacktraces: Node/JS, Python, Java, Go regex → `file:line` extraction; map to `git ls-files`; ignore non-tracked
- Accept `crash.log` file or `npm start 2>&1 | smart-git trace` (stdin)
- Flags: `--stacktrace <path>` (file), stdin fallback, `--limit 10` (top N culprits), `--oneline`
- *Why P0: highest frequency pain, lowest friction, defines product. From Idea #1.*

**2. Blame + SZZ origin finder + ranking**
- For each `file:line`: `git blame` → candidate commits → walk with `git log -S/-G` to find origin (added vs modified)
- Rank by: origin vs last-touch, recency, touch-count on that line, author
- Output: ranked table `rank | hash | date | author | message | file:line | added/modified`
- *Why P0: moat vs plain `git blame`; no new dep, just git plumbing.*

**3. Noise filter (lite) — no tree-sitter yet**
- Re-rank with `git show --ignore-all-space --ignore-blank-lines`; if diff is whitespace/import-only → demote culprit, show greyed out
- Detect renames (`git log --follow --diff-filter=R`)
- *Why P0: kills ~50% Prettier/rename false blames for ~20 lines of code. Full AST (Idea #3) is v1.1: add `trace --semantic` with tree-sitter when lite proves insufficient.*

**4. Output & inspect**
- Human: table + `diff snippet` (3 lines context) per culprit
- Machine: `trace --json` for CI/IDE
- `smart-git show <hash>` alias passthrough + `--verbose` prints blame chain
- *Why P0: table stakes for demo + scripting.*

**5. `smart-git lens <hash> --preview` — Time-travel preview (lite)**
- Ephemeral `git worktree` at culprit hash, `git show` hunk side-by-side of the exception line, `lens --exit` cleans up
- No PR/CI/Revert automation yet — just `worktree + diff`
- *Why P0: closes loop find→understand without stashing. Lite version is ~30 lines (worktree add/remove). Full `lens --revert/create-branch + PR link` (Idea #5) is v1.1.*

### P1 — Table stakes (ship with P0, trivial)

**6. CLI skeleton**
- `smart-git --help`, `--version`, exit codes (0 found, 1 not found, 2 bad input), `--verbose`
- Auto-detect repo root (`git rev-parse --show-toplevel`), error if not a git repo

**7. Zero-config, zero new deps**
- Node CLI, only `git` as runtime dep. No tree-sitter, no embeddings, no worktree daemon.

### Out of scope for v1.0 → v1.1 (deliberately deferred)

| Deferred | From | Why not v1.0 | When to add |
|----------|------|--------------|-------------|
| Full Semantic Blame (`trace --semantic` AST) | Idea #3 | Needs tree-sitter per language, heavy, lite filter covers 50% | v1.1 if lite still shows Prettier false positives |
| Bisect Buddy (`hunt --repro ./repro.sh`) | Idea #2 | Needs repro script (narrows audience), worktree orchestration, build-skip heuristics — second product | v1.1 as `smart-git hunt` |
| Delta Detective (`search --exception`) | Idea #4 | Fuzzy keyword/embeddings, low precision, tuning risk; only matters when line moved | v1.1 if users report stale traces |
| Lens full (`lens --revert`, PR/CI metadata, reviewer) | Idea #5 | Needs GitHub API, auth, branching UX — polish, not wedge | v1.1 |

## What v1.0 is NOT

- Not a bisect tool, not a search engine, not an AST platform. One wedge, well executed.
- No config file, no daemon, no embeddings, no language server.

## Acceptance (demo script)

```bash
npm start 2>&1 | smart-git trace              # stdin
smart-git trace --stacktrace crash.log --json  # file + json
smart-git trace --limit 3 --oneline           # compact
smart-git lens abc1234 --preview               # worktree preview
smart-git lens --exit                          # cleanup
```

If this gif doesn't make a dev say "that's 10x faster than manual blame," v1.0 failed.
